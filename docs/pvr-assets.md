# PNG assets to PVR files

The repository keeps the public texture API deliberately small: `Texture::upload()`
accepts row-major 16-bit ARGB4444 pixels, while the KOS backend uploads them as a
non-twiddled texture. A Dreamcast `.PVR` file normally contains a `PVRT` header
and a twiddled payload, so the advanced controller lesson demonstrates the
conversion boundary explicitly instead of pretending that a filesystem path is
already a texture handle.

## Convert a PNG with KOS `pvrtex`

Use the `pvrtex` utility shipped with the pinned KOS toolchain. For a square
transparent PNG such as `advanced_examples/assets/controller.png`:

~~~sh
/opt/toolchains/dc/kos/utils/pvrtex/pvrtex \
  -i advanced_examples/assets/controller.png \
  -o advanced_examples/assets/controller.pvr \
  -f argb4444 \
  -p /tmp/controller-preview.png
~~~

The checked conversion was made with KOS `pvrtex` 2.00. `-f argb4444` keeps
four-bit alpha, red, green, and blue channels; the default square output is
twiddled and uncompressed. The preview is useful for checking the converter’s
quantization before committing the binary file. Keep dimensions at a power of
two supported by the texture API, preferably square for this `.PVR` container.

Do not pass `--stride` for this example. Stride output is non-twiddled, but the
`.PVR` writer uses other container types for rectangular or strided textures and
the lesson is specifically teaching the square-twiddled `PVRT` path.

## How the example uses the file

The build does not add a converter tool or a runtime filesystem dependency. The
committed `controller.pvr` is mirrored into
`advanced_examples/assets/controller_pvr.hpp` as a generated byte array so the
ELF remains self-contained when packaged by the project’s current ELF-only CDI
rule. `advanced_examples/02-controller-pvr.cpp` validates the `PVRT` header,
decodes the ARGB4444 twiddled payload from Morton order into row-major pixels,
and then calls the normal `Texture::upload()` API. This is an educational loader
for the one format used by the lesson, not a general PVR reader.

If the PNG changes, rerun the converter, regenerate the byte-array header from
the resulting `.pvr` with any binary-to-C++ dumper, and rebuild. The `.PVR`
file remains the source asset; the header is only the embedding representation.
The current implementation intentionally does not claim support for mipmaps,
VQ compression, palette formats, GBIX chunks, or rectangular textures.

The controller example renders a full-screen opaque blue quad first, then draws
the PVR on the punch-through list. Transparent texels therefore reveal the
the PVR's global `PT_ALPHA_REF` threshold to `0x80`, so fully transparent
ARGB4444 texels are discarded while the controller remains visible. Transparent
texels therefore reveal the background and make an accidental opaque black
rectangle visible in the Flycast check. Emulator validation is not hardware validation.
